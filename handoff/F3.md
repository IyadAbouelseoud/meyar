## Implementation plan

### Shape
A dependency-free Node 22 app in `kit/` (same approach as `cds/`: `node:http`, `node:fs`, WebCrypto). No npm packages, so nothing new to approve.

| File | What it does |
|---|---|
| `kit/lib/chain.js` | Isomorphic ES module (Node + browser). Canonical JSON (sorted keys), `hash = SHA-256(prevHash + canonicalJSON(event))`, genesis `prevHash` = 64 zeros. `verifyChain(events)` returns per-event status and the first broken link. Enforces the event order. |
| `kit/lib/events.js` | The six events in order: `issued`, `collected`, `sealed`, `shipped`, `received`, `genotyped` (Arabic + English labels, clinician voice). |
| `kit/lib/fhir.js` | Builds the FHIR R4 `Specimen` (identifier `urn:meyar:kit` = kit ID, subject by identifier `urn:meyar:patient`, the system A4 uses) and one `Provenance` per event (target = Specimen, `recorded`, `occurredDateTime`, `location` display, `agent.who` display, `activity` from a kit CodeSystem, hash + prevHash + seq in extensions, `meta.tag` mock). Parses Provenance back into an event, so verify can run on what HAPI holds. |
| `kit/lib/fhir-client.js` | Small `fetch` client for the local HAPI at `http://localhost:8080/fhir` (env `FHIR_BASE`). Never the public server. |
| `kit/lib/store.js` | Local ledger `kit/data/<kitId>.jsonl` (gitignored), one event per line. Source of truth when HAPI is offline; mirrored to HAPI when online. |
| `kit/lib/handoff.js` | On `genotyped` (only if the chain verifies): writes `<outDir>/<patientId>.origin.json` = `{"sampleOrigin":"germline"}` and `<outDir>/<patientId>.kit-handoff.json` (kitId, Specimen ref, VCF path, chain head hash, mock). Default outDir `kit/out/engine-handoff/`; `ENGINE_IN_DIR=engine/data/in` writes straight into the engine's input folder (runtime output, not a repo edit). |
| `kit/web/barcode128.js` | Code 128 (set B) encoder, SVG out, in the browser. Tube label. |
| `kit/web/qr.js` | QR encoder (byte mode, ECC level M, auto version, mask scoring), SVG out, in the browser. Mailer label. Content: `MEYAR-KIT:<kitId>` only, no patient data. |
| `kit/web/index.html` + `kit/web/app.js` + `kit/web/kit.css` | Timeline screen. Arabic first (`lang="ar" dir="rtl"`), English toggle, `paper` theme + chart paper, clinician voice, `.m-chain`, `.m-status`, `.m-proto`, `.m-mock`. Scan field (a USB barcode scanner types the code + Enter), "Record next event" with place and actor, Verify button, Simulate edit / Restore for the demo, labels panel (Code 128 + QR). kit.css uses tokens only. |
| `kit/server.js` | Serves `kit/web/`, `/design/*` read-only from `../design`, and the JSON API: `GET /api/kits/:id`, `POST /api/kits/:id/scan`, `GET /api/kits/:id/verify?source=ledger|fhir`, `POST /api/kits/:id/tamper`, `POST /api/kits/:id/restore`, `POST /api/kits/:id/reset`. Port **5174** (new, not one of the pinned ports; env `KIT_PORT`). |
| `kit/test/*.test.mjs` | `node --test`. Chain valid over six events; editing any one event breaks verify at exactly that event; deleting/reordering is caught; out-of-order scan refused; Code 128 checksum and an independent decode; QR structure; FHIR mapping round-trip; hand-off writes germline origin that `engine/origin_guard.py` accepts; HAPI integration (skipped loudly if HAPI is down). |

### Demo data

### Honesty
- "Research prototype — not for clinical use" and "Demo data" on every screen.
- No specimen stability numbers, no transit-time limits, no temperatures.
- A hash chain is tamper-evident, not tamper-proof: anyone who can rewrite every record can rebuild the chain. Said in the UI and README; production would sign events and anchor the head hash outside the store (future deployment step).
